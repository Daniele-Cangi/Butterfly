# Butterfly Visual Identity Skill
## Theme: Forensic Diorama

Butterfly must feel like a small causal world under observation.
The visual direction is not generic SaaS, not AI-neon, not game HUD.

## Core feeling
Warm editorial worldbuilding + precise causal instrumentation.

## Visual goals
- Make the world feel like a crafted diorama / maquette.
- Make the interface feel like a technical observation tool.
- Make the MomentFrame feel like a documented artifact, not a generic preview card.
- Make simulation details visually attractive without turning the app into a dashboard.

## Style rules

### Color
Use a restrained palette:
- paper / warm neutral backgrounds
- dark ink text
- teal for routes and structural motion
- muted rust for constraint/closure
- muted gold for recovery preview
- subdued red for impossible
- smoky neutral for unknown

Avoid bright neon and oversaturated gradients.

### Typography
Use two families with clear roles:
- editorial serif for titles, moment labels, major headings
- technical sans or mono for data, timestamps, patches, state labels, inspector details

Titles should feel authored.
Data should feel exact.

### Materials
- soft matte surfaces
- subtle borders and dividers
- minimal shadows
- no heavy glassmorphism
- no glossy UI

### Motion
- slow and deliberate
- no flashy transitions
- transitions should clarify state changes
- the same timestamp must drive every representation in the active view

### Causality language
Use recurring visual language for:
- direct cause
- indirect consequence
- impossible
- unknown
- satisfied requirement

Do not rely on color alone.
Use line style, opacity, icon shape, and labeling.

## Priority surfaces
Focus on these components first:

1. Main diorama view
2. Timeline
3. MomentFrame
4. Recovery alternative cards
5. Causal inspector
6. Version selector (Original / Your variant / Recovery preview)

If time is limited, improve these before any secondary styling.

## MomentFrame rules
MomentFrame must become a signature element.

It should:
- look like a documented frame or exhibit plate
- clearly show target time
- show status
- preserve elegance when the moment fails
- show absence through composition, not fake presence
- remain synchronized with the active version and target time

## Technical charm
Make technical details visually compelling:
- patch operations
- event times
- simulation states
- causal reasons
- revision labels

These should feel precise and desirable, not dry.

## Anti-patterns
Do not implement:
- AI startup aesthetics
- glowing cards
- all-caps cyberpunk
- giant dashboards
- permanent graph spaghetti
- overly gamified badges
- decorative 3D that disconnects from actual simulation state

## Acceptance criteria
The design pass succeeds if:
- the app is recognizable at a glance
- the user immediately understands there is a world, a change, and a consequence
- the MomentFrame feels iconic
- the technical layer looks trustworthy and attractive
- the interface no longer looks like a generic prototype
