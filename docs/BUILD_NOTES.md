## Review regression suite

The external review suite exposed cases where the simulator had used event ID order as a proxy for time: location checks could run before an earlier trip, derived facts could be missed, and location after a later trip used the first movement. A follow-up case showed that resolving every same-key fact producer could manufacture a cycle when a future restock depended on the current checkpoint. Fact reads now resolve only producers whose earliest possible completion is at or before the read time. A truly self-produced requirement still raises a cycle error. Future effects do not count as current facts, and missing current facts remain unknown. The cases are retained in `tests/review-regressions.test.ts`.

Verification after the fix: `npm test` passed all 18 behavior tests, `npm run test:browser` passed all 3 Chromium flows, `npm run typecheck`, `npm run lint` and `npm run build` passed. The browser regression checks two restock IDs (`a-restock` and `z-restock`) against the same checkpoint result, as well as a true self-cycle. The first mobile screenshot captured the lazy-loading placeholder; the browser test now waits for the 3D canvas before capturing it.

At the end of Phase 2 no Sanity project credentials were configured, so live Content Lake reads, Studio login, seed and publication were not represented as tested. Phase 3 later found an authenticated CLI session but insufficient dataset permissions; see the Phase 3 notes below. No App SDK app, Workflow or AI runtime was installed. The Director is an authenticated Studio custom tool.

`npm audit fix` without forced major changes could not clear all transitive advisories. Updating compatible `styled-components` and Vitest releases reduced the audit from 18 to 14 findings (11 moderate, 3 high). The remaining high findings are in Sanity CLI transitive packages (`adm-zip`, `js-yaml`, `smol-toml`); npm proposed a breaking Sanity downgrade, which was not applied. Review these upstream dependencies before a public deployment, especially any privileged authoring environment. A clean `npm ci` from the lockfile succeeded after the updates.

## Phase 3: temporal state and Sanity connection

Continued from the verified `6fb6ba4` repository state on `codex/phase-3-state-sanity`; no history reset or destructive Git operation was used.

The engine now evaluates `entityAt` through the same timed route sampler used by the scene. It returns a known origin before a planned departure, a definite place while waiting, no definite place during movement, and the destination at exact arrival. In-progress transports cannot become their own preconditions; a genuinely earlier in-progress transport needed by a later location read raises a named temporal cycle. `sampleRoute` no longer borrows the position of a later stop before departure. Fractional simulation minutes remain unrounded; only the `HH:mm` display rounds to the nearest minute.

MomentFrame subjects and props now pass through pure selectors that consult the active world/result at the featured time. Composition points are applied only after presence at the required place is established. Absent subjects are omitted; unknown subjects render translucent at their last known location and the overlay reports uncertainty. Arrangements require successful completion plus the prop still being at the plaza. Selecting a MomentFrame version keeps the scene, event statuses, inspector, accessible clock and timeline display on the same time; range input and arrow shortcuts cannot move it until returning to the neighborhood.

Sanity schemas now include explicit event/operator choices, conditionally visible fields, interval and duration checks, and full-world adapter validation inside Studio. The Director offers **Reload draft** and displays validation errors without falling back to the fixture. The active reader checks pointer/revision/snapshot identities; publication independently validates and simulates authored content, creates a full snapshot and atomically patches the pointer with `ifRevisionId`. Seed, status and publication CLI commands can use the logged-in Sanity CLI client or a server/CLI token. A local test makes a concurrent pointer revision change immediately before transaction commit and verifies that the new pointer is retained without a new frozen revision.

The Sanity CLI was already authenticated to project `xamw5g7s`; the only existing dataset was `production`. A scoped, read-only query found no documents with Butterfly IDs, and an anonymous pointer query returned no document. The idempotent seed then received HTTP 403 from Content Lake: the logged-in role lacks `create`. The transaction created no Butterfly content. The embedded Studio loads Sanity's **Connect this Studio to your project** prompt, which requires adding the local origin to project CORS. No dataset, CORS setting, API token, or remote revision was created or changed. The app's local environment points to that project/dataset so the home page honestly reports **Local sample (live unavailable)** while no active pointer exists. Live editorial proof, seed, Studio editing and publication remain unverified due to these exact project permissions/settings.

The first browser test run found an ambiguous selector (two causal buttons) and a test that expected the missed variant while the selected view was still the recovery preview. The test was changed to select **Your variant** explicitly; this preserves the product behavior and tests the intended version. The configured Studio needs an idle wait before showing Sanity's CORS state.
